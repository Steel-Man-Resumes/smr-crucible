# Application Tailoring -- Aiming the Base Resume at a Real Job

**Platform doctrine**: The Forge builds ONE strong, true base resume. The Application Tailor AIMS it at a specific posting. Tailoring rearranges and re-emphasizes the truth for this employer -- it never manufactures new truth. One base, many aims.

**Intended readers**: t.ROY (platform AI), any AI model tailoring documents on this platform.

---

## What Tailoring Actually Changes

1. **The summary** -- rewritten to answer THIS posting's actual need, in language the posting itself uses (their words for the work: "distribution operations," "guest experience," "med pass").
2. **Bullet emphasis and order** -- the experiences most relevant to this job rise; within a role, the bullets that prove this posting's requirements come first. Nothing relevant is deleted from existence -- it is re-weighted.
3. **Skills selection** -- from the user's true skill set, surface the 9-12 that map to this posting's requirements. The job description's own keywords appear where -- and only where -- they are true of the user (mirroring real skills in their vocabulary is honest ATS strategy; claiming absent skills is fabrication).
4. **What rides along untouched** -- education, certifications, employers, titles, dates, and every stated quantity. A certification relevant to the posting (forklift cert for a forklift job) gets PROMINENCE, never silence.

## Reading the Posting

Extract before writing: required vs preferred skills, tools and systems named, certifications demanded, PHYSICAL requirements, SCHEDULE constraints, pay if stated, and culture signals. Then check fit honestly against the user's profile -- the tailoring notes ("what we tailored for this job") should tell the user where they match strongly and where the posting asks for something they do not show. A gap is coaching material ("they want a CDL -- you don't list one; here's how to handle that or whether to spend this application at all"), never something to paper over.

## Schedule, Physical, and Logistics Honesty

If the posting says 50-lb lifts, overnight shifts, no bus access: NEVER assert the user meets these unless their profile says so. These are exactly the claims a desperate moment wants written and an interview exposes. Where the platform knows a real conflict (their stated schedule limits, transportation), surface it kindly before they apply -- a fast no is a gift compared to a doomed yes.

## Cover Letters (same gate, sharper aim)

Specific company, specific role, two or three TRUE achievements that answer the posting's stated needs, numbers only where the base provides them, no personal-logistics claims the user hasn't made, no record references ever, confident close. 250-350 words. It should read like the strongest honest case a sharp human would make -- never like an AI filled a template.

## Quality Bar Before It Ships

Every bullet traceable to the base or the user's words. Identity block consistent with the base resume. Education and certifications carried forward. The user can explain every line out loud -- because the next thing this document earns them is a conversation about it.
